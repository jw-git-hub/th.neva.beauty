# Дизайн-спека: сайт th.neva.beauty

Дата: 2026-07-30

## Цель

Пересобрать сайт салона красоты на острове Самуи со старой Tilda-выгрузки
(`doctor-cosmetolog.pro`, бренд «Avocado Beauty - Samui») на статический генератор,
скопированный с боевого `vn.neva.beauty`. Услуги и цены переносятся со старого сайта
без изменений; концепция, дизайн и техническая архитектура — с vn.

Новый домен: **th.neva.beauty**. Новый бренд: **Neva Beauty — Koh Samui**.

## Архитектура

Генератор vn копируется целиком и перенастраивается. Ничего в его устройстве
не переделывается: модель данных совпадает со структурой старых страниц.

```
th.neva.beauty/                  ← репозиторий
├─ generator/
│  ├─ build.py                   оркестратор сборки
│  ├─ schema.py                  JSON-LD граф schema.org
│  ├─ check_prices.py            парити-тест цен
│  ├─ check_content.py           новый: проверки качества страниц
│  ├─ data/
│  │  ├─ site.yml                бизнес, контакты, конфиг
│  │  ├─ content.yml             тексты, FAQ, таксономия
│  │  └─ prices.json             эталон цен (источник истины)
│  └─ templates/                 Jinja2-шаблоны и партиалы
├─ th.neva.beauty/               сгенерированный сайт → GitHub Pages
├─ .github/workflows/deploy.yml  CI/CD
└─ requirements.txt
```

Сборка детерминирована: один проход `build.py` превращает данные в готовый сайт.
Пуш в `main` запускает GitHub Actions, который собирает сайт и деплоит на GitHub Pages
на домен из `CNAME`.

### Почему копия, а не общий движок

Два сайта расходятся сильнее, чем совпадают: разная валюта, разное число разделов,
разная вёрстка прайса, разный набор услуг. Общий пакет пришлось бы параметризовать
под каждое расхождение и версионировать, а любая правка требовала бы регрессионной
проверки боевого vn. Для двух сайтов это дороже, чем разовый перенос улучшений руками.

## Модель данных

Структура старых страниц ложится на модель vn один в один:

| Старая страница | Поле в модели vn |
|---|---|
| Заголовок H1 | `services.<slug>.title` |
| Вводный абзац | `services.<slug>.intro` |
| Блок «Преимущества» (4–6 карточек) | `services.<slug>.benefits` |
| Прайс с секциями | `prices.json[slug] = [{section, items}]` |
| Уточнение под позицией | `items[].desc` |

Пример реальных данных со страницы «Уход за волосами»: секции «Стрижки», «Окрашивание»,
«Осветление»; позиция «Детская — 1200 ฿» с уточнением «до 10 лет».

### Константы бизнеса (`site.yml`)

```yaml
brand:          "Neva Beauty"              # короткая форма — для title
brand_full:     "Neva Beauty — Koh Samui"  # полная форма — шапка, футер, schema, тексты
brand_location: "Koh Samui"
location:       "о. Самуи, Таиланд"
hours:          "Приём по записи"
base_url:       "https://th.neva.beauty"
metrika_id:     99850063
contacts:
  whatsapp_url:  "https://wa.me/79990289115"
  telegram_url:  "https://t.me/shyrakras"
  instagram_url: "https://www.instagram.com/avocado.beauty.samui/"
business:
  type:          "BeautySalon"
  telephone:     "+79990289115"
  currency:      "THB"
  currency_note: "Указаны в тайских батах (฿)."
  language:      ["Russian", "English"]
  language_code: "ru"
  address:
    locality: "Koh Samui"
    region:   "Surat Thani"
    country:  "TH"
```

**Правило написания бренда.** Полная форма «Neva Beauty — Koh Samui» используется
в шапке, футере, `schema.org` и хотя бы раз явно в тексте каждой страницы — это нужно
для единообразия сущности бизнеса в глазах поиска и ИИ. В `title` используется короткая
форма «Neva Beauty», потому что полная съедает 23 символа из лимита в 60 и у длинных
услуг («Кератиновое выпрямление волос», «Davines Naturaltech Tailoring») заголовок
обрезался бы в выдаче. Окончательные формулировки `title` утверждаются на этапе
SEO-оптимизации каждой страницы.

Данные юридического лица на сайте не публикуются — решение заказчика. В `schema.org`
бизнес описывается как `BeautySalon` без реквизитов.

## Изменения в генераторе

### 1. Параметризация захардкоженного под Дананг

| Файл | Что захардкожено | Куда выносим |
|---|---|---|
| `build.py` | `OUT = ROOT.parent / "vn.neva.beauty"` | путь выходной папки |
| `build.py` | «— Neva Beauty» в заголовках privacy и 404 | `site.brand` |
| `build.py` | `https://vn.neva.beauty` в генерации sitemap | `site.base_url` |
| `build.py` | текст `llms.txt` про Дананг и Вьетнам | `content.llms_description` |
| `service.html.j2` | alt «— Neva Beauty, Дананг» | `site.brand_full` |
| `service.html.j2` | «Указаны во вьетнамских донгах (đ)» | `site.business.currency_note` |
| `check_prices.py` | путь `vn.neva.beauty` | путь выходной папки |

### 2. Прайс переверстывается в таблицу

Оба промта (SEO и GEO) требуют, чтобы цены были настоящей `<table>` — так их корректно
читают и поисковые системы, и ИИ-ассистенты. Сейчас в vn прайс собран из `<div>`.

Разметка: `<table>` с `<caption>`, `<thead>` («Услуга» / «Цена»), `<tbody>`,
`<th scope="row">` на названии позиции. Визуально результат неотличим от текущего vn —
те же стили, те же табы разделов, те же карточки комбо-наборов.

Правки затрагивают `service.html.j2`, `assets/css/service.css` и селекторы
в `check_prices.py`.

### 3. Починка расчёта диапазона цен

`price_aggregate()` в `build.py` сейчас вычисляет диапазон для `AggregateOffer` так:
вырезает из строки цены все символы кроме цифр. На простых ценах Дананга это работает,
на ценах Самуи ломается. Из 203 позиций 16 записаны не простым числом (ниже — образцы
всех встречающихся форматов):

```
'600 -1200 ฿'   → 6001200   ← в разметку попадёт цена 6 001 200 ฿
'500-1000 ฿'    → 5001000
'400 -1000 ฿'   → 4001000
'300–500 ฿'     → 300500
'от 2500 ฿'     → 2500      корректно
'от 500 ฿'      → 500       корректно
'+500 ฿'        → 500       доплата, не самостоятельная цена
'+1500 ฿'       → 1500      доплата, не самостоятельная цена
'35 ฿/минута'   → 35        поминутный тариф, не разовая цена
```

Некорректный диапазон в структурированных данных — это риск ручных санкций Google,
поэтому алгоритм переписывается:

1. Строка, начинающаяся с `+`, считается доплатой и в расчёт диапазона не идёт.
2. Строка, содержащая `/` (тариф за единицу времени), в расчёт не идёт.
3. Из остальных строк извлекаются **все** числа; каждое участвует в поиске минимума
   и максимума.
4. Если чисел нет, позиция пропускается.

На отображение цены на странице это не влияет — там цена выводится дословно.

### 4. Новые проверки качества (`check_content.py`)

Скрипт для этапа аудита, падает при нарушении:

- ни в одном файле нет строк `Avocado`, `avocado`, `doctor-cosmetolog.pro`;
- у каждой услуги задана картинка и файл существует;
- все внутренние ссылки ведут на существующие страницы;
- `title` и `meta description` уникальны на всём сайте и укладываются в лимиты;
- на каждой странице ровно один `<h1>`;
- каждый блок JSON-LD парсится как валидный JSON.

## Карта страниц

25 страниц: главная + 5 разделов + 17 услуг + политика + 404. Индексируемых — 23.

| Раздел | URL раздела | Услуги |
|---|---|---|
| Волосы | `/volosy/` | `/uhod-za-volosami/`, `/tokio-inkarami/`, `/biozavivka-volos/`, `/keratinovoe-vypryamlenie-volos/`, `/davines-naturaltech-tailoring/` |
| Эпиляция | `/epilyaciya/` | `/lazernaya-epilyaciya/`, `/elektroepilyaciya/`, `/saharnaya-epilyaciya/` |
| Аппаратная косметология | `/apparatnaya-kosmetologiya/` | `/igolchatyj-rf-lifting/`, `/smas-lifting/`, `/udalenie-tatuirovok-lazerom/`, `/fotoomolozhenie-m22/` |
| Косметология | `/kosmetologiya/` | `/uhodovaya-kosmetologiya/`, `/botulinoterapiya/` |
| Коррекция фигуры | `/korrekciya-figury/` | `/endosfera-terapiya/`, `/massazh/` |
| Макияж | своей страницы нет | `/permanentnyj-makiyazh/` |

Служебные: `/privacy/`, `/404.html` — обе `noindex`, в sitemap не попадают.

У раздела «Макияж» одна услуга. Генератор в этом случае не создаёт страницу раздела,
а ведёт пункт меню сразу на услугу — логика `is_page = len(services) > 1` уже есть в vn.

Пять слагов совпадают с vn (`lazernaya-epilyaciya`, `smas-lifting`, `endosfera-terapiya`,
`udalenie-tatuirovok-lazerom`, `fotoomolozhenie-m22`) — это работает на единообразие сети.

**Сахарная эпиляция** на старом сайте была страницей-сиротой: страница существовала,
но ссылок на неё не было ниоткуда. На новом сайте она включена в меню и в перелинковку.

Страница `/store` не переносится: магазин отключён, а товары на старом сайте
подгружались через API Tilda и в выгрузке отсутствуют.

## Точность цен

Требование заказчика: цены и перечень услуг переносятся со старого сайта без изменений.
Защита выстроена в три уровня.

1. **Извлечение.** Скрипт парсит 17 старых страниц и собирает `prices.json`
   (203 позиции). Скрипт одноразовый, живёт вне репозитория.
2. **Сверка.** Отчёт кладёт рядом позиции старой страницы и позиции `prices.json`
   по каждой услуге. Отчёт вычитывается, спорные места выносятся заказчику отдельно.
3. **Парити-тест.** `check_prices.py` при каждой сборке парсит готовый HTML и сверяет
   каждую позицию с `prices.json`, падая при любом расхождении. Запускается и локально,
   и в CI.

Цена на странице выводится дословно как на старом сайте. Единственная нормализация —
отступ перед знаком ฿ (на старом сайте встречается и `500 ฿`, и `500฿`).

## Изображения

На каждой старой странице услуги ровно одно осмысленное фото — это 17 героев.
Плюс герой главной и 6 обложек разделов из фотографий старой главной.
Итого 24 изображения.

Исходники горизонтальные (1680×1120 и подобные), а шаблон услуги ждёт вертикальный
кадр 760×950, как в vn. Обработка: кроп по центру в пропорцию 4:5, ресайз до размеров vn,
пересохранение в WebP с JPG-фолбэком, переименование из tilda-мусора
(`tild3630-3034-4261-a338-646436343937__1.webp`) в осмысленное (`lazernaya-epilyaciya.webp`).
Качества исходников достаточно: после кропа остаётся запас по разрешению.

Отдельно готовится горизонтальная картинка 1200×630 для превью в соцсетях
и мессенджерах: вертикальный герой на эту роль не годится. На старом сайте превью
не работало вовсе — путь в `og:image` был относительным.

## SEO и GEO

### Заложено на этапе сборки

- `<html lang="ru">`, canonical на `https://th.neva.beauty/...`, `hreflang` ru + x-default;
- Open Graph с абсолютным `og:image` (на старом сайте путь был относительным
  и превью не работало), Twitter `summary_large_image`;
- JSON-LD граф: `Organization` + `BeautySalon` + `WebSite`, на страницах —
  `Service`, `BreadcrumbList`, `FAQPage`, `ItemList`, `AggregateOffer`;
- `sitemap.xml`, `robots.txt` с разрешением ИИ-ботам (`GPTBot`, `OAI-SearchBot`,
  `Google-Extended`, `PerplexityBot`, `ClaudeBot`, боты Яндекса), `llms.txt`;
- Яндекс.Метрика 99850063 на всех страницах.

`BeautySalon` описывается без `streetAddress` и без `geo`: `addressLocality` — Koh Samui,
`addressRegion` — Surat Thani, `addressCountry` — TH. `currenciesAccepted` — THB,
`priceCurrency` в офферах — THB, `areaServed` — Koh Samui.

Отзывы и рейтинги (`Review`, `AggregateRating`) не добавляются: реальных отзывов
на страницах нет, а фейковая разметка отзывов ловится Google и ведёт к санкциям.

### Проработка по промтам

Глубокая оптимизация выполняется отдельными сессиями, по странице за раз, по промтам
из `Данные и промты /`: сначала промт 1 (SEO), затем промт 2 (GEO/AEO) для той же
страницы. Промты предполагают, что страница уже существует и наполнена, поэтому базовый
текст пишется на этапе сборки.

Базовый текст сразу соблюдает жёсткие ограничения промтов: не обещает результат,
не выдумывает факты, называет бренд и локацию явно. Старые тексты этого не соблюдали
(«удаление волос навсегда», «гарантированно разрушает волосяной фолликул»,
«безболезненное») и переписываются.

## Работы вне этого репозитория

- Бэкпорт прайс-таблицы в `vn.neva.beauty` — там та же проблема с вёрсткой цен дивами.
- Переименование аккаунта Instagram: сейчас `avocado.beauty.samui`, то есть старый
  бренд. Устранить это в коде нельзя — только переименованием аккаунта, после чего
  старые ссылки автоматически ведут на новое имя. Отложено по решению заказчика:
  на первом запуске остаётся старое имя.
- Google Business Profile в режиме зоны обслуживания (адрес скрыт).
- Google Search Console и Яндекс.Вебмастер: подтверждение домена, отправка sitemap.
- Тайский номер WhatsApp вместо российского.

## Открытых вопросов нет

- **Часы работы.** Приём только по записи — подтверждено заказчиком. На сайте
  формулировка «Приём по записи», `openingHoursSpecification` в схему не добавляется.
- **Instagram.** Аккаунт `avocado.beauty.samui` со старым брендом остаётся как есть —
  решение заказчика, приведение в порядок отложено. Ссылка на него будет присутствовать
  в футере, кнопках записи и `sameAs` схемы на всех страницах.

## Вне объёма

- Мультиязычность сайта: сайт только на русском, английский указывается лишь как язык
  обслуживания в схеме.
- Каталог товаров и корзина.
- Отзывы и их разметка.
- Общий движок-пакет для двух сайтов.
- 301-редиректы со старого домена — домен удаляется сразу после запуска.
